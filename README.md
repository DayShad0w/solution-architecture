# RetailCore

Проектная работа курса «Архитектор решений», спринт 4. Кейс: платформа заказов розничного ритейлера. Java-монолит, Oracle с пакетами и staging-таблицами, рядом .NET и Python.

Репозиторий для сдачи должен быть публичным и называться `RetailCore`. На ревью отправляется ссылка на pull request.

## На чём держится решение

1. В `createOrder` статус `CONFIRMED` означает «платёжная сессия создана». Формальный цикл, который назвал техлид, устроен иначе. Пока это два языка, поддержка и отчёты будут видеть разные заказы. Первая точка трансформации — журнал фактов и история для поддержки, а не новый сервис статусов.
2. Оформление, оплата и выбор маршрута остаются в монолите. И спонсор, и техлид считают эту зону слишком дорогой для первого разреза. Учебная схема, где это отдельные компоненты, описывает имена блоков, а не границы развёртывания.
3. Первый этап — журнал фактов и история для поддержки. Фасад одного уже асинхронного партнёра и снятие одного показателя с операционной Oracle — следующие точки: без журнала их нечем кормить и нечем проверить. В целевую схему первого этапа они не входят.
4. Замена Oracle, разрез оформления и персонализация не являются точками трансформации. Их нельзя изменить в известных ограничениях, а эффект первого этапа они не проверяют. Срок импортозамещения никто не назвал.

## Чего в решении нет специально

Во входных материалах нет RTO, RPO, SLA, p95, RPS и допустимой задержки. Эти величины не подставлены. Список пробелов и кто их закрывает — в [Task1/requirements.md](Task1/requirements.md). Интервью с руководителем команды заказов и оформления в пакете материалов не было, сценарий для него подготовлен и в анализе помечен как непроведённый.

[Task3/transformation.md](Task3/transformation.md) заполнен по шаблону урока «Поиск точек трансформации»: бизнес-цель, уточнённые требования, ограничения, препятствия, точки и не-точки, приоритет, архитектура первого этапа, разрыв, метрики, риски. Базовые и целевые значения метрик в материалах не заданы и оставлены пустыми: названо, что измеряем и кто назначает порог.
