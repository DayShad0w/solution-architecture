# Solution-AdScale

Проектная работа курса «Архитектор решений». Кейс: интеграция SaaS-платформы AdScale с крупной DSP-площадкой без остановки текущего бизнеса.

Репозиторий для сдачи должен быть **публичным** и называться `Solution-AdScale`. На ревью отправляется ссылка на pull request.

## Как устроена работа

| Каталог | Содержание |
| --- | --- |
| [Task1](Task1/README.md) | Диагностика AS-IS, архитектурные драйверы, целевое видение, ADR |
| [Task2](Task2/README.md) | Сервис ставок, протоколы, API Gateway для DSP, надёжность |
| [Task3](Task3/README.md) | Данные, масштабирование, кэш, Kafka, отказоустойчивость |

Сквозная линия решений:

1. Монолит не выдерживает уже текущие 15 000 RPS (P95 110–120 ms при норме ≤ 100 ms). Новый партнёр требует около 80 ms и сразу поднимает пик до 18 000 RPS.
2. За три месяца систему не переписывают. Новый трафик DSP выносится на отдельный путь по образцу Strangler Fig. Старые рекламодатели остаются на монолите.
3. Через год платформа — набор сервисов с отдельными хранилищами, событийным контуром и запасом до 50 000 RPS, SLA 99,9%, два региона.

Ключевое ограничение горячего пути: ответ на bid request не ждёт PostgreSQL, финансовый сервис, аналитику и Kafka.

## Допущения

В постановке нет части количественных данных. Ниже — допущения, на которых держится решение. Если договор с партнёром или фактический профиль другие, меняются размеры, но не границы сервисов.

1. «Стабильное время ответа не более 80 ms» — это P95 на границе AdScale для нового DSP. Текущий внутренний порог P95 ≤ 100 ms сохраняется для уже подключённых партнёров.
2. 18 000 RPS — обязательный пик через 3 месяца. 50 000 RPS — целевая мощность через год (мультиплатформенность и запас), а не прогноз ровно на удвоение текущих 15 000.
3. Активных line items — порядка 10⁴–10⁵. Это позволяет держать проекцию кандидатов в памяти процесса ставок.
4. Сейчас один production-регион. Второй регион — цель горизонта года, не трёх месяцев.
5. Команда может взять управляемые PostgreSQL, Redis и Kafka. Отдельного SRE нет, свой большой кластер данных в первые три месяца не поднимаем.
6. Партнёр говорит на OpenRTB 2.6 (JSON over HTTPS).
7. Показы и клики приходят отдельными запросами после ответа на аукцион, а не внутри bid request.
