# Задание 1. Анализ текущей интеграционной архитектуры

**Цель:** описать системные проблемы и риски, которые могут помешать успешному запуску мобильного приложения «Здоровье+». Фокус — надёжность интеграций, масштабируемость и безопасность.

Проблемы отранжированы по влиянию на запуск приложения. В колонке «Признаки» указаны подтверждающие артефакты: тикеты Jira (INT-*), Service Desk (SD-*) и цитаты из интервью сотрудников.

| Проблема | Признаки | Влияние на приложение |
| --- | --- | --- |
| **1. Нет идемпотентности на операциях записи и оплаты.** Повторный POST (ретрай клиента, двойное нажатие) создаёт дубли. | INT-005 (Blocker, «дубли записей при повторных POST»), SD-003 («дважды нажал „Записаться" → две записи»), Дмитрий («идемпотентности нет»), INT-001/SD-009 (двойное списание). | Ключевой сценарий «запись к врачу» работает нестабильно уже на тесте. Без идемпотентности мобильное приложение (ненадёжная мобильная сеть → частые ретраи) будет массово плодить дубли записей и платежей. |

Доставка результатов из LIS в CRM ненадёжна и медленна.** FTP падает (425), нет авто-переотправки, задержка до 2 часов, дубли XML, застревание в очереди. | INT-002 (Major, «FTP падает 425… задержка до 2 часов»), INT-008 (Major, дубли XML → дубли анализов), INT-011 (Major, «LIS передал, CRM не обновила — застряло в очереди»), SD-005 («FTP-скрипт падал… запускали вручную»), Елена, Анна («задержка на несколько часов… врач не видит»). | «Получение результатов анализов без звонка» — один из главных сценариев MVP. Сейчас пациент не увидит анализы онлайн, а врач получит неактуальные или задвоенные данные. |

Интеграция мобильного приложения дорога и рискованна, нет защиты периметра. |

## Вывод

Большинство проблем носит системный, а не точечный характер: это свойства интеграций (отсутствие идемпотентности, гарантированной доставки, отката, единой точки входа), а не единичные дефекты кода. Поэтому целевая архитектура (Task2) строится вокруг четырёх опор — API Gateway с идемпотентностью и rate limiting, событийная доставка результатов анализов, сага для записи с оплатой и изоляция legacy (1С, LIS) кэшем, circuit breaker и anti-corruption layer. Эти проблемы напрямую адресуются в заданиях 3 и 4.
