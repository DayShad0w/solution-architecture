# Матрица решений: что покупать, что переносить, что оставить

Три модели из постановки:

- **SaaS** — чужой готовый сервис для функции, которая не отличает сеть.
- **PaaS** — своя логика на управляемой платформе. Сюда же относится отказ от сервера в магазине в пользу облачной базы и своих сервисов.
- **In-house** — продукт или система записи, которые остаются у VitaStore. SAP при этом остаётся on-premise: перенос всей ERP в облако в этот проект не входит.

Пример из задания («касса → SaaS, потому что это стандарт») здесь сознательно сдвинут. Касса стандартна по смыслу, но российский фискальный контур, работа без интернета и уже написанные Promo Engine и Smart Fulfillment делают чужой кассовый SaaS заменой одной жёсткой связки на другую.

| Возможность                                    | Где болит сейчас                                                   | Решение                                 | Почему так                                                                                          |
| ---------------------------------------------- | ------------------------------------------------------------------ | --------------------------------------- | --------------------------------------------------------------------------------------------------- |
| Пробитие чека и фискализация                   | Толстый клиент, свой код в каждом контуре магазинов                | PaaS, свой тонкий клиент                | Типовая функция, но чек должен печататься без сети, а цены и акции берутся из своих систем          |
| Эквайринг и драйверы терминалов                | Отдельный драйвер на каждый банк, Сбербанк ARCUS-2 не подключается | PaaS, свой HAL и платёжный шлюз         | Код кассового ПО не должен знать протокол терминала. Банк остаётся банком, прослойка (шлюз) — наша  |
| Инкассация                                     | Локальный регламент                                                | SaaS банка                              | У банков это штатный сервис                                                                         |
| Печать ценников                                | Следствие локальной базы                                           | Часть Cloud POS                         | Отдельный продукт не нужен, цены приезжают из каталога                                              |
| Click & Collect                                | Зависит от того, открыт ли магазин и актуальны ли остатки          | In-house, Smart Fulfillment             | Это и есть отличие сети. В магазин ставится только выдача заказа                                    |
| Маппинг номенклатуры при покупке магазина сети | Почта, Excel, 500 позиций в час, до двух недель                    | PaaS, свой сервис сопоставления         | Правила сопоставления завязаны на эталон SAP. Человек остаётся на исключениях                       |
| Эталонный каталог                              | Уже в SAP                                                          | In-house, SAP                           | Система записи. Второй каталог в SaaS создаст ещё один маппинг                                      |
| Promo Engine                                   | Уже централизован                                                  | In-house                                | Своя логика акций. Хостинг можно позже вынести, продукт не покупается                               |
| Приём товара от локальных поставщиков          | Дубль ERP в магазине                                               | In-house, SAP                           | Приёмка должна попадать в общий учёт, а не в местную базу                                           |
| Остатки магазина                               | Локальный SQL, ночной файл                                         | PaaS, центральный учёт                  | Иначе Click & Collect продаёт товар, которого на полке нет                                          |
| Лояльность «в тетрадке»                        | Не работает без сети и не связана с центром, не централизовано     | In-house, лояльность SAP                | Баллы уже есть в SAP. Тетрадку убираем. Офлайн работа кассы не должна блокировать формирование чека |
| Премии продавцов                               | Считаются в магазине                                               | SaaS или модуль SAP HR                  | Кадровый учёт, не должно происходить на уровне архитектуры фронтов (касс)                           |
| Сервер и СУБД магазина                         | Железо, лицензии, диск как единая точка отказа                     | Убрать. Данные в управляемой PostgreSQL | Прямая причина высокого TCO                                                                         |
| Финансы и кадры HQ                             | SAP                                                                | In-house, on-premise                    | Система записи и контур, который в этом проекте не мигрируем                                        |

## Что не переносится в облако

SAP ERP остаётся в контуре штаб-квартиры. В облако уезжают кассовый трафик, каталог для магазина и сопоставление номенклатуры. Promo Engine и Smart Fulfillment остаются продуктами компании: облачная касса их вызывает, но не подменяет.
