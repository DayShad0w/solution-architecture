# Офлайн и синхронизация

Покупатель с наличными должен уйти с фискальным чеком, даже если в магазине нет интернета. Для этого планшет не ходит за каждой ценой в облако. В начале смены и дальше по расписанию, пока есть связь, Edge Agent скачивает снимок каталога, цен и открытой смены и держит его локально. Чек за наличные считается на этом снимке. HAL передаёт его на ККТ по локальному порту, регистратор печатает фискальный документ и хранит его в фискальном накопителе. Облако для печати не нужно. Карта в этом режиме выключена: авторизацию делает банк, без канала её не получить. Лояльность тоже не блокирует продажу. В инциденте INC-8402 чек вставал именно из-за таймаута баллов. В целевой схеме баллы либо ставятся в ту же очередь и дописываются позже, либо кассир явно продаёт без них.

Каждый такой чек получает ключ, который касса создаёт один раз. Пока связи нет, документ лежит в локальной очереди со статусом «не отправлен». Edge Agent сам проверяет канал. Когда HTTPS до API Gateway снова открывается, он отправляет пачку. Сервис синхронизации в облаке принимает чек только если такого ключа ещё не было: повтор после обрыва посередине отправки не создаёт вторую продажу. После записи в управляемую PostgreSQL сервис публикует событие продажи. На него списывается остаток, чек уходит в фискальный контур и дальше в ОФД, а Edge Agent помечает локальную копию как принятую. Конфликт цены, если в штаб-квартире ценник успели сменить, пока магазин был офлайн, не переписывает уже пробитый чек. В учёт попадает фактическая цена продажи, а расхождение остаётся отдельной записью для разбора.

Локальная очередь не заменяет сервер магазина. В ней нет базы сети и нет лицензии SQL. Это журнал одной кассы на время обрыва. Если точка не выходит на связь дольше согласованного окна, дежурная смена видит это по отсутствию heartbeat, а не по звонку из магазина о неработающем ПК.
