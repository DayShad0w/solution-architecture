### Список систем: анализ функциональных пробелов
|**Система**|**Функциональность (новая/существующая)**|**Комментарий (что нужно доработать)**|
|---|---|---|
|**ИС «Алмазы»** (существующая)|**Отбор алмазов для цифрового аукциона** (новая)|Требуется внедрение статусной модели (State Machine) для блокировки алмазов от двойной продажи и отслеживания статусов (отправлен в лабораторию, на аукционе). Для MVP1 — реализация экспорта/импорта каталога через Excel.|
|**ИС «Логистика»** (существующая)|**Отправка алмазов в лабораторию и возврат в офис** (новая)|Необходимо настроить новые маршруты и точки погрузки/разгрузки. Требуется добавить функционал End-to-End трекинга для закрытия «слепых зон» во время нахождения сырья у внешнего подрядчика.|
|**ИС «Аукцион»** (существующая)|**Публикация данных и проведение онлайн-аукциона** (новая)|Полное отсутствие клиентского интерфейса. Требуется разработка Frontend-портала (витрины), модуля аутентификации/авторизации (RBAC) и внедрение S3-совместимого хранилища для отображения тяжелых медиафайлов (3D-сканы алмазов).|
|**ИС «Бухгалтерия»** (существующая)|**Актирование и оплата услуг лаборатории** (новая)|Процесс типовой, но требуется заведение новых контрагентов (договоры с лабораторией) и справочников. В целевом решении (MVP v2) — доработка API для приема автоматических триггеров на биллинг.|
|**ИС «Лаборатория»** (новая, внешняя)|**Оцифровка камней и формирование паспорта** (новая)|Внешняя система. Для наших бизнес-целей требуется договориться с вендором о формировании выгрузок в стандартизированном формате (JSON/XML) для автоматизированного парсинга в наш контур.|
|**Облачные сервисы** (новые)|**Хостинг витрины и файлового хранилища** (новая)|Требуется развертывание инфраструктуры (IaaS/PaaS), настройка сетевой связности (VPN/mTLS) с локальным контуром компании и установка средств защиты (WAF, Anti-DDoS).|
### Список интеграций: анализ информационных потоков
|**Интеграция (новая/существующая)**|**Как будет реализована (автоматически или вручную)**|**Какие будут передаваться данные (новые или существующие)**|
|---|---|---|
|**ИС «Алмазы» → ИС «Логистика»** (существующая)|**Вручную** (в MVP1 через выгрузки/заявки) ➔ **Автоматически** (в MVP2 через API)|**Новые:** План-заявки на перемещение по новым маршрутам (офис ↔ лаборатория). **Существующие:** Идентификаторы камней, паспорта.|
|**ИС «Лаборатория» → ИС «Аукцион»** (новая)|**Вручную** (в MVP1 через SFTP/Excel/защищенные архивы) ➔ **Автоматически** (в MVP2 через защищенный B2B-шлюз/API)|**Новые:** Результаты оцифровки камня (размер, чистота, флуоресценция, внутренние трещины, 3D-модели, медиафайлы).|
|**ИС «Лаборатория» → ИС «Алмазы»** (новая, _выявленный gap_)|**Вручную** (в MVP1 через реестры) ➔ **Автоматически** (в MVP2 по REST API/Webhook)|**Новые/Существующие:** Передача статуса (камни приняты на оценку / оценка завершена) для снятия блокировки в ИС «Алмазы» и инициации обратной логистики.|
|**ИС «Лаборатория» → ИС «Бухгалтерия»** (новая)|**Вручную** (в MVP1 обмен сканами актов/ЭДО) ➔ **Автоматически** (в MVP2 через интеграционную шину)|**Новые:** Акты оказанных услуг по оцифровке сырья, суммы к оплате, реквизиты (под вопросом, т.к есть ЭДО).|
|**ИС «Логистика» → ИС «Бухгалтерия»** (существующая)|**Автоматически / Вручную** (в зависимости от текущей реализации)|**Существующие:** Акты услуг ТК. **Новые:** Тарификация и акты по новым маршрутам до лаборатории (аналогично, есть ЭДО).|
